## الهدف

اعتماد تنسيق تقرير **طباعة التقرير والنتائج** كمرجع ذهبي (Golden Reference)، مع توحيد التصميم بين نسخة الويب (HTML/JavaScript) ونسخة Flutter (PDF)، دون إجراء أي تعديل على منطق الحسابات أو البيانات.

# توحيد المنصات (Platform Parity)

تم اعتماد توحيد تنسيق التقرير بين:

* ✅ نسخة الويب (HTML/JavaScript).
* ✅ نسخة Flutter (PDF).

بحيث تكون:

* نفس ترتيب الأقسام.
* نفس الألوان.
* نفس أحجام العناصر.
* نفس الهوامش.
* نفس أسلوب عرض الجداول.
* نفس تصميم بطاقات الشركاء.

---

# سياسة التجميد (Freeze Policy)

اعتبارًا من هذا الاعتماد، يُمنع إجراء أي تعديل على:

* تنسيق PDF.
* ألوان التقرير.
* أحجام الخطوط.
* ترتيب الأقسام.
* تخطيط الصفحة.
* تصميم الجداول.
* تصميم بطاقات الشركاء.
* الترويسة.
* التذييل.

ولا يُسمح بأي تعديل مستقبلي إلا في إحدى الحالتين:

1. إصلاح خطأ حرج (Critical Bug).
2. إضافة بيانات جديدة مطلوبة رسميًا دون تغيير التصميم المعتمد.

---

# ثبات واجهة البرمجة (API Stability)

يشمل التجميد كذلك الواجهة البرمجية الخاصة بخدمة الطباعة، بحيث لا يجوز تغيير أسماء الدوال أو تواقيعها (Function Signatures) أو طريقة استدعائها إلا في حالة إصلاح خطأ حرج أو عند إصدار نسخة رئيسية جديدة (Major Version).

ويشمل ذلك على سبيل المثال:

* `printReport(...)`
* `exportAndShareCroquisImage(...)`

وذلك لضمان عدم كسر أي شاشة أو خدمة تعتمد على هذه الواجهة مستقبلاً.
